# Phases

Ship order mirrors the operator's actual workflow — author the PRD, then iterate on the next loop. Each milestone gets a real project run-through before the next starts.

**v0.1 — PRD authoring + Requirements Loop.** The `prd-authoring` skill is fully fleshed out for monolithic PRD drafting with senior-PM posture and critique on demand. The `requirements-loop` orchestrator subcommand ships. The `prd-to-frds` generator skill runs autonomously and iteratively. All four requirements-loop reviewer skills land: `req-spec-judge`, `req-cross-doc-judge`, `req-coverage-judge`, `req-scoping-judge`. Loop-level state file and verdict parsing are in place. The `requirements/_questions-pending.md` mechanism and `awaiting_clarification` verdict are wired up with the dual completion condition (reviewers pass plus zero open questions). A `Stop` hook on reviewer subprocesses validates the single-trailing-line `VERDICT: pass|fail` format. No mirrors; local only. Exit criteria: the operator authors a PRD in a new project repo, runs `requirements-loop`, and ends up with a reviewed FRD tree they are willing to blueprint against.

**v0.2 — Blueprint Loop and non-blocking clarifications.** The blueprint artifact shape is pinned: three blueprint types (container, component, feature) with per-type document structure (sections, mention syntax, fenced `component`/`model` blocks, ADRs) adopted from the SF blueprints module's seeded category presets. On-disk layout `blueprints/{containers,components,features}/<slug>.md` plus dotted-hidden meta files mirrors the requirements tree. The `blueprint-loop` orchestrator subcommand ships. A single `frd-to-blueprint` generator skill writes all three blueprint types itself (no sub-skill co-invocation). The interactive `blueprint-authoring` skill (renamed from `foundation-blueprint-authoring`) lands as an operator-driven editing skill, not orchestrator-spawned. The `blueprints_communication/` folder lifecycle is wired up (same shape as `requirements_communication/`). The orchestrator handles the `awaiting_clarification` verdict for the blueprint loop (same verdict and mechanism as the requirements loop) and the dual completion condition (all reviewers pass plus zero open questions in `blueprints/_questions-pending.md`). All four blueprint-loop reviewers ship: `bp-spec-judge`, `bp-coverage-judge`, `bp-consistency-judge`, `bp-decision-judge`. Exit criteria: the blueprint loop produces reviewed blueprints for the v0.1 project, with at least one real clarification cycle (loop stops with open questions → operator answers → loop runs again and completes).

**v0.3 — Coding Loop sequence generation.** Pin the work-order artifact shape based on blueprint-loop learnings. The `coding-loop` orchestrator subcommand ships with sequence generation only (execution deferred). The `blueprint-to-tasks` and `scope-task` generator skills land. All three sequence-gen reviewers ship: `wo-scoping-judge`, `wo-coverage-judge`, `wo-dependency-judge`. The flat `work-orders/wo-NNN/` layout with `.sequence.meta.yaml` for blueprint-change detection is in place. Exit criteria: a reviewed, ready work-order sequence exists for the v0.2 project.

**v0.4 — Coding Loop execution (tests gate).** Per-work-order execution subprocess wired into `coding-loop`. Tests gate only; no LLM reviewers yet. Generator opens PR on first pass. State file per work order; PR comment mirroring. One work order at a time; queue drain respects `blocked_by[]` and `sort_order`. Exit criteria: the first work order is merged to `main` of the v0.3 project from an autonomous coding-loop run.

**v0.5 — Coding Loop LLM reviewers.** The `spec-judge`, `regression-judge`, `security-judge`, and `quality-judge` gates ship. The Playwright gate for UI-touching work orders ships via `run-playwright-check`. Status transitions are fully automated end-to-end across all three loops.

**v1.0 — Polish.** Software Factory mirror ships once SF has an upload API. Operator documentation lands: README, runbook, failure-mode catalog derived from the first twenty real work orders. A skill and reviewer-name consistency pass renames coding-loop execution reviewers to `code-*`. Ad-hoc operator-invokable review skills ship for each artifact type (blueprint, work order, code). An `index-updater` agent and `harness/index.md` round out the release.
