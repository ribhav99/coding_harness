# Product Description

The coding harness is a reusable kit for running long-horizon software engineering work through Claude Code autonomously, with verification as the primary correctness gate. A single operator takes a project from a drafted product description to merged pull requests without sitting inside the intermediate decomposition, scoping, and per-work-order execution stages.

The product moves a project through four stages — one manual, three autonomous. The operator opens a Claude Code session and drafts a single monolithic `PRD.md` at the project repo's root using the `prd-authoring` skill. That PRD is the only artifact the operator writes by hand. Three autonomous loops follow: the Requirements Loop decomposes the PRD into a structural tree of product-overview sections and Feature Requirements Documents; the Blueprint Loop turns approved FRDs into technical blueprints, bubbling up architectural decisions that need operator judgment; the Coding Loop generates an ordered work-order sequence from the blueprints and then drives each work order through an autonomous gen/review cycle to a reviewed pull request ready for the operator to merge.

Each autonomous loop shares the same mechanic. An orchestrator spawns a generator subprocess, then spawns each reviewer subprocess, aggregates their verdicts, re-spawns the generator with aggregated feedback on any failure, and commits the artifact on all-pass. The same plumbing — state files, reviewer review files, PR-comment mirroring, budget enforcement — runs all three loops. They differ only in generator skill, reviewer set, target artifact tree, and (for the blueprint loop) the dual completion condition that couples reviewer pass to an empty decisions doc.

Claude Code is the runtime. The orchestrator never makes direct Anthropic API calls — every model interaction goes through `claude -p` as a subprocess. This inherits every Claude Code improvement for free and leverages the Claude Max subscription rather than per-token billing. The orchestration surface stays thin — a Python loop that spawns subprocesses and aggregates verdicts, backed by in-session hooks, skills, and subagents.

Local files are the source of truth. The canonical PRD, FRDs, blueprints, work orders, and execution state live at the project repo's root under `requirements/`, `blueprints/`, `work-orders/`, `artifacts/`, and `harness/`. The entity layout mirrors Software Factory's model so mechanical upload to SF (or any future external system) is possible. External backends are optional outbound mirrors, never alternative queues — the orchestrator always reads from and writes to local files.

The product serves one persona and is scoped accordingly. It is a personal tool for a single technical operator running Claude Code on their own projects, not a team-scale product. It does not pursue multi-user polish, cross-agent portability, autonomous PRD writing, chat-style assistant flows, or token-level cost optimization. Wall-clock throughput is the budget unit. Autonomy lives inside each loop; handoffs between loops are discrete, operator-visible gates. The PRD is human. Bubble-ups during blueprint synthesis are human. Merge is human. Everything else is autonomous.
